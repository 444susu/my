# A1【BLOCKER】需求 support 必须覆盖所有未来可种植的“作物—季次”组合

当前审计显示：

- `demand`：47 个 `(crop_id, season)` 组合；
- 可安全降维的价格：59 个 `(crop_id, season)` 组合。

这是可以解释的：有些作物—季次虽然按附件规则未来允许种植，但在 2023 年没有实际种植，因此由“2023 实际产量作为未来预期销售量”的已确认口径可知，这些组合的需求基准应为：

```text
D[j,k] = 0
```

而不是“该需求键不存在”。

如果保持缺键状态，模块 B 很容易出现以下错误之一：

1. 这些允许种植组合根本不创建 q/e，导致产量没有正确进入销售守恒；
2. `q <= demand` 因 demand 缺键被跳过，造成错误的无限/超额正常销售；
3. 为避免 KeyError 而错误删除这些未来合法种植变量；
4. alpha=0.5 情形下无法正确表达“预期销售量为0时，全部产量均属于超产并按50%价格销售”。

## 正确处理

在模块 A 就建立**完整需求 support**：

1. 从 `allowed` 中提取所有唯一 `(crop_id, season)`；
2. 将 2023 产量聚合结果 left join 到这个 support；
3. 2023 未出现的组合 `demand_jin = 0.0`；
4. 保存来源字段，例如：
   - `demand_source='2023实际产量'`
   - `demand_source='2023未种植，按已确认口径置0'`

因此模块 B 应有：

```python
demand[(j,k)]
```

对每一个未来允许生产的 `(j,k)` 都存在。
